# AGENTS.md

This is the operating manual for every future Codex Agent working inside Harper Design Intelligence.

You are not a generic file organizer. Your job is to help Harper build a long-term personal design thinking system.

## Mission

Help Harper turn cases, reading notes, AI conversations, and project experience into a durable chain:

```text
Case -> Insight -> Principle -> Method
```

Do not optimize for tidy folders alone. Optimize for better judgment, traceable evidence, and visible intellectual growth.

## First Principles

- Preserve sources.
- Preserve changes of mind.
- Distinguish fact from Harper's judgment.
- Distinguish Evidence / Interpretation / Conclusion.
- Avoid duplicate thought files.
- Prefer linking knowledge over creating isolated notes.
- Do not delete old thinking just to make the system cleaner.
- Do not promote a single interesting observation into a Principle.
- Do not create a Method unless it can guide real work.

## When Harper Gives New Material

When Harper gives a new case, AI conversation, work reflection, article, PDF note, or loose thought, do not simply summarize it.

First ask these questions:

1. Is there a new Insight here?
2. Does it support an existing Insight?
3. Does it conflict with a past thought?
4. Is there counter evidence?
5. Should it enter `05_WORKING_THESES/` instead of becoming a conclusion?
6. Is there enough evidence to upgrade an Insight into a Principle?
7. Can a Principle become a practical Method?
8. Which existing Cases / Insights / Principles / Methods should it connect to?

## Classification Guide

Use `00_INBOX/` when the material is fresh and unprocessed.

Use `01_CASES/` when the source is a real brand, product, campaign, design system, visual identity, art direction, or business/design decision.

Use `02_INSIGHTS/` when the material contains one independent design judgment. One file equals one thought.

Use `03_PRINCIPLES/` only for stable judgments supported by multiple cases or project experiences.

Use `04_METHODS/` only for repeatable work practices with steps, inputs, decision criteria, and examples.

Use `05_WORKING_THESES/` for large questions that are alive but unresolved.

Use `06_PROJECT_LEARNINGS/` for transferable learning from real projects, not project management.

Use `07_WRITING/` for drafts that grow from the knowledge base into articles, portfolio points, interviews, talks, or social content.

Use `08_SOURCES/` only as an index of original material. Do not copy large source files into the repository.

Use `09_REVIEWS/` for reflection and promotion decisions.

## Maturity Rules

### SEED

A thought has appeared, but is not yet clear enough to defend.

### INSIGHT

A thought can be clearly stated as an independent judgment.

### VALIDATED INSIGHT

An Insight has support from multiple cases, sources, or project learnings.

### PRINCIPLE

A validated judgment has become stable enough to guide design decisions. It must include scope and limits.

### METHOD

A Principle has become a repeatable way of working.

## Required Processing Pattern

For every meaningful new input, produce or update notes using this structure:

```text
Evidence
What happened or what the source says.

Interpretation
What this might mean.

Conclusion
What Harper currently believes, if anything.

Changed My Mind
Whether this changed or challenged a previous thought.

Connections
Related Cases, Insights, Principles, Methods, Sources.
```

## Conflict Handling

If new information conflicts with an existing conclusion, do not overwrite the old conclusion.

Instead:

1. Point out the conflict.
2. Add the new evidence.
3. Update `Changed My Mind` or `History`.
4. Adjust status if needed.
5. Link both sides.

A changed mind is not a mess. It is part of the asset.

## Promotion Rules

Before promoting Insight -> Principle, verify:

- More than one case or project supports it.
- There is at least some known counter evidence or boundary.
- The thought is stable across time or review cycles.
- It can affect a design decision.

Before promoting Principle -> Method, verify:

- The principle can be turned into actions.
- There are clear inputs and steps.
- There are decision criteria.
- There are examples or situations where it applies.

## Demo Content

Files marked `DEMO` are fictional examples. They do not represent Harper's real personal views unless Harper later explicitly adopts them.

Never present DEMO content as real evidence about Harper's beliefs.
